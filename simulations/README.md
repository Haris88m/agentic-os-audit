# The Simulation Suite

Five numeric studies of the CONSUME architecture (Apex Prime). Every figure, table and chart in the assessment documents is generated by this code — nothing is hand-drawn.

## Run it

```bash
cd simulations
python run_all.py        # Python 3.10+, standard library only, deterministic (fixed seeds)
```

Regenerates everything under [`results/`](./results/): one `.csv` + `.json` + `.svg` per study.

## The honesty-label system

Carried over from the v1 audit and extended with one label:

- **VERIFIED** — reproduced or directly inspected; for cost studies, pure arithmetic on published list prices.
- **PARTIAL** — supported but bounded evidence.
- **SIMULATED** — output of a stated model. Every simulation's docstring declares its full parameter set, which parameters are **anchored** (to a public ledger, a published study, a dated real-world event, or a published price) and which are **assumptions** (and those are sensitivity-swept). A simulation quantifies a structural argument; it does not measure the future, and these documents never pretend otherwise.

## The one measured anchor that matters most

Simulation 3's CONSUME swap-time distribution is anchored to a real, dated event: on **2026-06-11**, four days ahead of an announced provider billing change, the production 9-agent fleet behind this assessment moved its entire reasoning engine to a different provider (DeepSeek V4 Pro) behind one environment knob — designed, implemented, sealed, and verified live (9/9 agents answering) the same day. The coupled-architecture migration band it is compared against is an assumption, and the results table sweeps it from optimistic (7–21 days) to pessimistic (30–90 days).
